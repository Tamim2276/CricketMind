# CricShot10k / CricketMind

Two pieces of work share this repository.

| | **CricketMind** | **The accuracy work** |
|---|---|---|
| What | an agentic architecture in which fabricated numbers cannot reach the user | beating 89.09% on CricShot10k shot classification |
| Code | [`cricketmind/`](cricketmind/), [`notebooks/`](notebooks/) | [`src/`](src/), [`configs/`](configs/) |
| Results | [`paper/CricketMind_ICCIT/`](paper/CricketMind_ICCIT/) (submitted, 6 pages) | [`experiments/*/checkpoints/`](experiments/) |

Base dataset: Dihan et al., *CricShot10k: A Large-Scale Video Dataset for
Cricket Shot Classification*, IEEE Access 2026 (doi:10.1109/ACCESS.2026.3663220).

---

## Running it

```bash
python -m pytest                      # 113 checks, ~20 s
jupyter lab notebooks/                # the two notebooks
```

**Use `.venv`.** There are two Python 3.10 installs on this machine with the
same packages, and it is easy to run tests in one while editing for the other:

```bash
source .venv/Scripts/activate         # git bash
.venv/Scripts/python.exe -m pytest    # or call it directly
```

If you see `No module named pytest`, you are in `.venv` and it is missing:
`.venv/Scripts/python.exe -m pip install pytest`.

`torch` is installed **per machine** with a different wheel — do not pin it in
a shared requirements file, or one of the two setups breaks:

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/xpu   # Arc B580
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124 # RTX 3070
pip install langgraph langchain-core pydantic ipykernel pytest                   # both
```

Everything resolves its device at runtime through
[`src/utils/device.py`](src/utils/device.py) (XPU → CUDA → CPU), so no script
hardcodes a backend.

## Layout

```
cricketmind/              the architecture, as a package
  config.py               constants, and Settings -- the one object a run varies
  state.py                CricketMindState, its reducers, trace
  corpus.py               the synthetic evidence the stub graph retrieves over
  agents.py               the twelve stakeholder agents + the sanctioned facts
  llm_router.py           the optional Qwen2.5-7B router, via Ollama
  graph.py                build_cricketmind_graph -- all 30 nodes
  steps.py                the seven intermediate graphs, for the walkthrough
  nodes/                  perception, grounding, analytics, routing,
                          verification, output
  experiments/            measurement: profile, routing_eval, boundary,
                          figures, tables
notebooks/
  01_walkthrough.ipynb    how the graph is built, one stage at a time
  02_results.ipynb        the three results; writes the paper's four tables
tests/                    the checkpoint assertions, as pytest
tools/nbstrip.py          keep notebook outputs out of git diffs
src/, configs/            the CricShot10k training code (separate paper)
paper/                    the ICCIT submission and its figure blueprint
```

**Notebooks import; they do not define.** Every node, constant and experiment
lives in the package, so the notebooks cannot drift from what the tests check.
To change behaviour, edit the package.

## Settings: why there are no global knobs

Everything about a run that is not the query — the stub confidence, tracing,
which agents fabricate, which router proposes — is a field on `Settings`, and
it travels inside the graph state:

```python
from cricketmind import CLIP, QUERY, Settings, build_cricketmind_graph, new_state

graph = build_cricketmind_graph()
final = graph.invoke(new_state(CLIP, QUERY, Settings(
    confidence=(0.40, 0.92),            # fails the gate once, then passes
    lie_once={"n11b_tactical_analysis"} # Coaches fabricates on its first try
)))
print(final["report"])
```

These used to be module-level globals that cells reassigned — `STUB_CONFIDENCE`
alone was reassigned twelve times — so running cells out of order silently
changed results, and every scenario needed a `try/finally` to put them back.
Now two runs cannot interfere with each other, and
`tests/test_experiments.py::test_scenarios_do_not_leak_into_each_other`
checks it by running the scenarios in reverse.

## The paper's numbers

All four tables in `paper/CricketMind_ICCIT/tables/` are generated by
`notebooks/02_results.ipynb`. Never edit them by hand — re-run the notebook.
`python -m pytest` checks the same results without starting Jupyter.

The language-model routing runs are cached in
`experiments/routing/llm_routing_runs.json`, so the results reproduce with
Ollama switched off. They are only re-run if the model, the run count or the
prompt list changes.
